## 結論

現在入手できる資料では、Homeについて「片側だけに空白を残さない」「末尾や途中の未使用列を必ず埋める」という明示ルールは確認できなかった。ただし、統合仕様が根拠に挙げるHome再設計の元資料そのものを確認できていないため、過去にそのルールが存在しなかったとは断定しない。

現存資料から確認できるのは、Curated Grid、画像を尊重すること、同一比率の強制と不必要なCropを避けること、通常MetadataとHover / Focus補助Metadataの区別までである。「空白があるから仕様通り」とする根拠も、「空白をすべて埋めることが仕様」とする根拠も、この範囲からは得られない。

## 実装上の原因をブラウザで再現

実データや参考実装のファイルは変更せず、独立したテスト用ブラウザの表示データだけを「横長1件＋縦長1件」にして確認した。

| 対象 | 配置 | 右側の未使用領域 |
| --- | --- | --- |
| 現在の体験版（1440px幅） | 4列中、横長が2列＋縦長が1列 | 346px（残り1列と間隔） |
| 変更していないv5参考実装（1440px幅） | 12列中、横長が6列＋縦長が3列 | 349.5px（残り3列と間隔） |

v5にも、この組合せの右側を自動で埋める処理はなかった。再現結果は [reproduction.json](reproduction.json) と [v5-reproduction.json](v5-reproduction.json)。これは「実装がそう動く」という確認であり、空白が正式設計で許容されたという証明ではない。

## 作業結果

今回変更したのは調査記録だけで、アプリの配置コードは変更していない。片側空白の禁止ルールを確認できない状態で、さらに別の配置方式へ変更して「仕様準拠」と説明することは避けた。
